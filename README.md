# 인연 페이북 (In-yeon Paybook)

경조사 지출과 참여 내역을 기록하고 통계로 확인하는 반응형 웹앱입니다. PRD v1.0 기준으로 구현했습니다.

**▶ 배포 주소: https://inyeon-paybook.vercel.app**

- 📱 **모바일 퍼스트 반응형** — 하단 탭 + 가운데 기록 버튼, PC 에서는 넓은 레이아웃
- 🔌 **오프라인 우선** — PWA. 홈 화면에 설치되고, 네트워크가 없어도 열립니다
- 🗄️ **저장소 교체형** — 기본은 이 브라우저(IndexedDB), Supabase 키를 넣으면 로그인 + 여러 기기 동기화

---

## 1. 실행

### 가장 쉬운 방법 — `실행.cmd` 더블클릭

필요한 준비(설치·빌드)를 알아서 하고 브라우저까지 엽니다. 같은 와이파이에 있는 휴대폰에서 접속할
주소(`http://192.168.x.x:4173`)도 함께 알려줍니다. **검은 창을 닫으면 앱도 꺼집니다.**

> ⚠️ `index.html` 을 더블클릭하면 열리지 않습니다.
> 루트의 `index.html` 은 빌드 전 템플릿이고, 웹앱을 `file://` 로 여는 것 자체가 막혀 있습니다
> (브라우저가 모듈 스크립트를 차단하고, 데이터 저장소·오프라인 기능도 동작하지 않습니다).
> 웹앱은 항상 주소가 있는 서버로 열어야 하고, `실행.cmd` 가 그 서버를 대신 띄워 줍니다.

코드를 고치면서 볼 때는 `개발모드.cmd` 를 쓰면 저장할 때마다 화면이 새로고침됩니다.

### 명령으로 실행

```bash
npm install
npm start          # 빌드 후 http://localhost:4173
npm run dev        # 개발 서버 http://localhost:5173
```

| 명령 | 설명 |
| --- | --- |
| `npm start` | 빌드 + 로컬 서버 (실행.cmd 와 같은 동작) |
| `npm run dev` | 개발 서버 (같은 와이파이의 휴대폰에서도 접속 가능) |
| `npm run build` | 프로덕션 빌드 → `dist/` |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm test` | 파싱·엑셀 매핑·집계 로직 스모크 테스트 |
| `npm run typecheck` | 타입 검사 |

키 설정 없이도 바로 동작합니다. 이 상태에서는 **데이터가 그 브라우저에만** 저장됩니다.

> 이 PC 를 켜두지 않아도 언제 어디서든 쓰고 싶다면 아래 2번의 배포까지 진행하세요.
> 배포하면 휴대폰에서 주소로 열고 홈 화면에 설치해 앱처럼 쓸 수 있습니다.

## 2. 어디서든 접근하려면 (Supabase 연결)

1. [supabase.com](https://supabase.com) 에서 프로젝트를 만듭니다.
2. **SQL Editor** 에 [`supabase/schema.sql`](supabase/schema.sql) 전체를 붙여넣고 실행합니다.
   테이블 · RLS 정책 · 실시간 구독 · 이미지 버킷이 한 번에 만들어집니다.
3. `.env.example` 을 `.env` 로 복사하고 **Project Settings → API** 의 값을 채웁니다.

   ```env
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

4. 앱을 다시 실행하면 로그인 화면이 나타납니다. (이메일+비밀번호 또는 메일 로그인 링크)

> 이미 로컬에 쌓아둔 기록이 있다면, 로그인 후 **설정 → 로컬 기록 올리기** 로 계정에 옮길 수 있습니다.
> `anon key` 는 공개되어도 되는 키입니다. `service_role` 키는 절대 넣지 마세요 — 모든 접근은 RLS 로 본인 데이터만 허용됩니다.

### 배포 (Vercel — 이미 연결되어 있습니다)

프로젝트: `dcs-kor/inyeon-paybook` · 주소: <https://inyeon-paybook.vercel.app>

```bash
npx vercel deploy --prod     # 코드를 고친 뒤 다시 올릴 때
```

`vercel.json` 에 SPA 폴백과 캐시 헤더(에셋 1년 immutable, 서비스워커 no-cache)를 정의해 두었습니다.
배포 직후 나오는 긴 주소(`...-hzte0j15t-...vercel.app`)는 Vercel 보호가 걸려 로그인 화면이 뜨는 게 정상이고,
누구나 여는 주소는 위의 짧은 주소입니다.

Supabase 를 붙였다면 배포 환경에도 같은 값을 넣고 다시 배포해야 합니다.

```bash
npx vercel env add VITE_SUPABASE_URL production
npx vercel env add VITE_SUPABASE_ANON_KEY production
npx vercel deploy --prod
```

메일 로그인 링크를 쓴다면 Supabase → **Authentication → URL Configuration** 의 Site URL 과
Redirect URLs 에 `https://inyeon-paybook.vercel.app` 을 추가하세요.

다른 곳에 올려도 됩니다 (Netlify · Cloudflare Pages · GitHub Pages). 빌드 명령 `npm run build`,
출력 디렉터리 `dist`, 정적 사이트라 서버가 필요 없습니다.

## 3. PRD 요구사항 대응표

### A. 데이터 입력

| 요구사항 | 구현 |
| --- | --- |
| 누가 (이름 + 관계) | 이름·관계 분리 입력. 관계는 이전에 쓴 값이 자동완성되고, 같은 이름이 있으면 관계를 제안 |
| 언제 (캘린더 위젯) | 네이티브 날짜 선택 + `오늘`/`어제` 바로가기, "3일 전" 상대 표시 |
| 어떤 일 (분류) | 부고 · 결혼 · 개업 · 축하 · 병문안 · 찬조 · 기타 (모바일에서 한 번에 고르는 7칸 그리드) |
| 얼마 (숫자 키패드, 천단위 콤마) | `inputMode="numeric"` 로 숫자 키패드 호출, 입력 중 콤마 자동 삽입, `+5만/+10만` 빠른 가산 |
| 화환 송부 / 직접 참석 | 토글 스위치 2개 |
| 비고 | 계좌번호·동행자 등 자유 메모 |
| 청첩장·부고장 이미지 저장 | 갤러리 선택 또는 드래그&드롭. 긴 변 1600px 로 자동 압축 후 저장 |
| 텍스트 붙여넣기 | 카카오톡 부고 문자·청첩장 문구를 붙여넣으면 **이름·날짜·분류·장소·계좌번호·금액**을 찾아 폼을 채우고 원문을 비고에 남김 |
| 엑셀 가져오기/내보내기 | 헤더를 추정해 매핑 화면을 채우고, 사용자가 고친 뒤 미리보기 → 등록. 내보내기는 `내역` + `요약` 두 시트 |

### B. 집계 및 대시보드

| 요구사항 | 구현 |
| --- | --- |
| 기간별 지출 집계 | 이번 달 총액(대문 숫자) + 올해 누적, 최근 12개월 막대 추이 |
| 카테고리 분석 | 분류별 막대 그래프 (금액·건수·비율을 막대마다 직접 표기) |
| 참여도 통계 | 직접 참석 비율 / 화환 송부 비율 + 기간 전환(이번 달·올해·전체) |
| 히스토리 검색 | `인맥` 탭에서 인물 검색 → 그 사람과의 모든 내역을 타임라인으로 표시 |

### C. 데이터 스키마

PRD 의 필드를 그대로 따르되 두 가지를 더했습니다.

- `relation` — PRD 의 `target_name` 예시가 `"홍길동(대학동기)"` 라 관계를 별도 컬럼으로 분리했습니다.
  화면과 엑셀에서는 여전히 `홍길동(대학동기)` 로 합쳐서 보여주고, 가져올 때도 괄호를 자동으로 분리합니다.
- `event_type` — 본문 목록(부고·결혼·개업·축하·병문안·찬조·기타)을 정본으로 삼았습니다.
  스키마 표에만 있던 `위로` 는 가져오기 시 `병문안` 으로 매핑합니다. (`부친상 → 부고` 같은 표기 흔들림도 정규화)

## 4. 엑셀 형식

기존 표의 헤더 이름이 달라도 가져오기 화면에서 직접 연결할 수 있습니다. 자동 인식되는 표기:

| 필드 | 인식하는 헤더 | 인식하는 값 |
| --- | --- | --- |
| 날짜 | 날짜, 일자, 일시, 경조일, date | `2024-03-05`, `2024.3.5`, `20240305`, 엑셀 날짜 서식 |
| 성명 | 성명, 이름, 대상자, name | `홍길동`, `홍길동(대학동기)` |
| 경조내역 | 경조내역, 분류, 구분, 사유 | `결혼`, `부친상`, `축의`, `위로` … |
| 금액 | 금액, 지출, 축의, 조의 | `100,000`, `100000원`, `5만` |
| 참석/화환 | 참석여부, 방문, 화환, 조화 | `O/X`, `참석/불참`, `TRUE/FALSE`, `Y/N` |
| 비고 | 비고, 메모, 내용 | 자유 텍스트 |

날짜나 성명을 읽지 못한 행은 등록하지 않고 **건너뛴 사유를 행 번호와 함께** 보여줍니다.

## 5. 구조

```
실행.cmd / 개발모드.cmd   더블클릭 실행기 (scripts/*.ps1 을 호출)
src/
  types.ts              분류 enum · 레코드 타입 · 이름/관계 분리 · 표기 정규화
  store.tsx             전역 상태(인증 · 목록 · CRUD) + 저장소 선택
  lib/
    repo/               저장소 어댑터 — types(인터페이스) / local(IndexedDB) / cloud(Supabase)
    excel.ts            엑셀 읽기 · 헤더 추정 · 행 변환 · 내보내기
    parseText.ts        부고 문자 / 청첩장 문구 파싱
    stats.ts            기간·분류·인물·관계별 집계
    format.ts           금액 · 날짜 포맷
    image.ts            첨부 이미지 압축
  pages/                Dashboard · Records · People · Settings
  components/           EventForm · EventCard · ImagePicker · ImportDialog · TrendChart · Login · ui
supabase/schema.sql     테이블 · RLS · 실시간 · 스토리지 버킷
tests/smoke.test.ts     파싱 · 매핑 · 집계 로직 테스트
```

화면 코드는 `Repo` 인터페이스만 알고 있어서, 로컬이든 Supabase 든 같은 코드로 동작합니다.
저장소를 바꾸고 싶다면 `src/lib/repo/` 에 구현 하나를 추가하면 됩니다.

### 알아두면 좋은 점

- **이미지**: 로컬 모드에서는 IndexedDB 에 저장되므로 그 브라우저에서만 보입니다. 계정으로 올릴 때 본문 기록은 옮겨지지만 이미지는 따라가지 않습니다 (다시 첨부해 주세요).
- **차트 색**: 분류 배지는 색과 이름을 **함께** 표시하고, 그래프는 단일 색 + 직접 라벨을 씁니다. 색각 이상이나 흑백 출력에서도 읽을 수 있게 한 선택입니다.
- **번들**: 엑셀(`xlsx`)과 차트(`recharts`)는 실제로 필요할 때만 내려받도록 분리해 두었습니다.
